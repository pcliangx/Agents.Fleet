## 1. Problem

同时使用多个 CLI 编码 Agent 很费精力：每个 Agent 都需要一个终端持续观察；普通终端或桌面应用关闭后，进程与上下文容易丢失；多个 Agent 在同一 Worktree 工作时会互相覆盖；用户缺少统一、可信的状态与结果视图。

用户希望把多个 Task 交给一个 Fleet 后离开电脑，回来时能够准确知道：

- 哪些 Agent 仍然 Alive；
- 哪些只是 Restored View；
- 哪些 Attempt 已失败、中断或处于 Uncertain；
- 每个 Attempt 修改、验证和遗留了什么。

## 2. Product Promise

Agents.Fleet v1 是本地优先的 macOS 桌面应用与用户级 Daemon：

- 每个 Task 在独立 Worktree 中执行。
- Daemon 独立于 Electron UI，UI 关闭或崩溃不终止 Alive Session。
- 用户重新打开 UI 后可 attach 同一个 Alive Session，或读取已经持久化的 Restored View。
- Daemon 或 Host 重启后，系统保留 Task、Attempt、Observation 和 Artifact，执行 Reconciliation，并如实显示 Interrupted / Uncertain。
- 原进程与 PTY 不会被描述为“跨机器重启存活”；resume 需要用户确认，并创建新的 Attempt 与 Session。
- Agents.Fleet 使用用户自己的 Agent、账号与 Host，不重新实现 Agent 的推理和工具循环。

## 3. Product Principles

1. **Truth before continuity**：宁可显示 Lost / Interrupted / Uncertain，也不把历史画面伪装成 Alive。
2. **UI is a projection**：UI 只订阅和提交命令，不拥有权威状态。
3. **Isolation by Worktree**：Fleet 管理的 Worktree 不被并发 Task 共享。
4. **Evidence over self-report**：结果由 Observation、Artifact 和 Git 事实支撑，不只展示 Agent 自述。
5. **Explicit trust**：Repository 默认 untrusted；安全承诺只覆盖 Fleet 真正能强制的行为。
6. **One reliable slice before breadth**：先完成单 Agent 可靠闭环，再增加并发和第二个 Adapter。

## 4. v1 User Stories

### 4.1 Trust, environment, and Workspace

- **TRUST-1**：首次打开 Repository 时，我必须在看到 canonical path、Agent 与实际权限披露后显式授予 Repository Trust。
- **TRUST-2**：我能选择 Manual / Balanced / YOLO，并在启动前看到对应 Agent 的 effective mapping、缺失控制与脱敏 argv 预览。
- **ENV-1**：我能看到 Git、shell、所选 Agent 的路径、版本、Capability 与可调用状态；若 Agent 依赖额外 runtime，也显示该依赖。
- **WORKSPACE-1**：我能导入本地 Git Repository，系统识别 Git root、默认 branch 和当前 commit，并建立 Workspace。
- **PROFILE-1**：我能保存不含明文秘密的 Agent Profile，并在创建 Attempt 时保存 Profile 快照。

### 4.2 Task, Attempt, and Worktree

- **TASK-1**：我能创建 Task，填写目标、背景、约束和验收标准。
- **WORKTREE-1**：首次执行 Task 时，系统从明确的 `baseCommitSha` 创建独立 Worktree；并发 Task 不共享 Worktree。
- **WORKTREE-2**：我能查看 Worktree 的路径、branch、Task、Alive Session、脏状态和清理阻塞原因。
- **WORKTREE-3**：删除 Worktree 前，系统检查 Alive Attempt、未提交修改、未合并 commit 和目标 identity，并允许保留 branch。
- **TASK-2**：每次首次执行、retry 或 resume 都创建新的 Attempt，旧历史不被覆盖。
- **TASK-3**：我能看到 Draft / Queued / Running / Waiting / Succeeded / Failed / Interrupted / Uncertain / Cancelled，并看到来源和原因。
- **TASK-4**：停止当前 Attempt 与取消整个 Task 是两个明确命令；两者都显示对 Alive Session 和未保存修改的影响。
- **TASK-5**：我能从原 Worktree、重新基线或指定 commit 创建 retry；每种选择都会预览新的 Worktree 和 `baseCommitSha`。
- **TASK-6**：Interrupted / Uncertain Attempt 不会自动重新执行；我确认后才能 resume，并得到新的 Attempt 与 Session。

### 4.3 Agent and Fleet

- **AGENT-1**：v1 支持 Claude Code 与 Codex；UI 按 Adapter Capability 展示 Hook、Transcript、Resume 和 Permission Mapping。
- **AGENT-2**：没有权威 Observation 的状态必须标记 inferred；没有 Resume Capability 时不显示 resume 操作。
- **FLEET-1**：我能在独立 Worktree 中同时运行多个 Task。
- **FLEET-2**：系统按 Host 与 Agent 并发上限把超限 Attempt 放入可见队列，空槽后按稳定顺序启动。
- **FLEET-3**：Fleet 看板展示当前 Task 状态、Agent、Worktree、等待原因、最近 Observation 和需要用户处理的项目。

### 4.4 Session continuity

- **SESSION-1**：关闭、重载或终止 Electron UI 后，Daemon 中的 Alive Session 继续运行。
- **SESSION-2**：重新打开 UI 后，我能在 1 秒预算内 attach 同一个 Alive Session，看到 Snapshot 与后续 delta，并继续输入。
- **SESSION-3**：我能明确区分 Alive、Exited、Lost 与 Restored View；Restored View 不能输入。
- **SESSION-4**：多个客户端可以观察同一 Session，但同一时刻只有一个 Attachment 持有 Control Lease。
- **SESSION-5**：旧 Attachment、旧 generation 或旧 fencing token 不能 input、resize 或 stop。
- **SESSION-6**：海量输出不会导致跨 Session 串线或静默丢失；达到存储硬上限时 Attempt 明确进入 Waiting / StoragePressure，相关进程组被暂停。
- **SESSION-7**：我能向 Alive Agent Session 发送 follow-up，输入会记录为带来源的 Observation。

### 4.5 Observation and results

- **OBS-1**：Task 时间线汇总创建、Attempt、输入、状态、Git 与完成事件，并区分 authoritative / inferred。
- **OBS-2**：我能查看 Worktree 文件树、staged / unstaged / untracked 状态、行级 diff、ahead / behind 和 branch 来源；v1 中这些能力只读。
- **OBS-3**：Attempt 结果页展示 Artifact、文件变化、commit、已观察到的测试结果、风险和数据缺口，不只依赖 Agent 自述。
- **OBS-4**：Agent 请求输入、Attempt 完成、失败、Interrupted、Uncertain 或 StoragePressure 时，我收到去重的桌面通知。

### 4.6 Security and distribution

- **SEC-1**：未授权客户端不能调用 Host 能力；Renderer 不能绕过 Electron Main 与 Daemon 的 Control interface。
- **SEC-2**：Fleet 自己的文件操作不能通过绝对路径、`..`、symlink 或竞态越过 Worktree root；UI 明确说明这不是 Agent sandbox。
- **SEC-3**：Fleet 管理的秘密进入 OS Keychain；普通日志和默认导出执行 best-effort redaction，并明确提示其限制。
- **DIST-1**：我能用签名并公证的 macOS 安装包安装应用，用户级 LaunchAgent 由系统托管。
- **DIST-2**：升级、卸载或数据清理遇到 Alive Session、脏 Worktree 或 Artifact 时，会显示影响并要求 drain、保留或取消。

## 5. Architecture and Module Decisions

### 5.1 Process model

- 用户级 LaunchAgent 运行 Daemon，拥有 PTY、子进程与生命周期权威；见 [ADR-0001](../adr/0001-user-launchagent-and-reconciliation-limits.md)。
- Electron Main 是 Control / stream transport adapter，Renderer 不直接取得 Host 能力。
- v1 的 Daemon crash 可能使 Session Lost；不引入 per-Session supervisor，也不承诺同一 PTY 跨 Daemon 或 Host 重启存活。

### 5.2 Deep modules

- **Control Dispatcher**：只负责版本、鉴权、幂等、确认与路由。
- **Task Orchestrator**：拥有 Attempt 状态机、队列、并发配额和 Reconciliation 决策。
- **Session Runtime**：拥有 PTY、进程组、Snapshot、chunk、cursor、背压和 Control Lease。
- **Worktree Manager**：拥有 provision、inspect、dispose 及全部 Git/path 安全不变量。
- **Agent Adapter**：隐藏 Agent 差异，并以 Capability 描述真实能力；见 [ADR-0002](../adr/0002-agent-adapter-capabilities.md)。
- **Fleet Projection**：从权威状态和领域事件生成 UI 读模型。

调用者和测试都通过这些 module interface 验证行为，不穿透 interface 断言内部状态。

### 5.3 Identity, persistence, and stream

- Task → Attempt → Session → Attachment 身份显式分层；attach 默认观察、控制权显式取得；见 [ADR-0004](../adr/0004-identity-and-observe-first-control.md)。
- SQLite 是生命周期、命令幂等和低频领域事件的唯一权威；PTY 字节使用独立 chunk store；见 [ADR-0005](../adr/0005-lifecycle-and-session-storage.md)。
- control 使用 NDJSON，stream 使用 length-prefixed binary frame。
- Session stream cursor 为 `{sessionId, generation, seq}`；Snapshot 声明 `coversThroughSeq`。
- 详细状态、故障矩阵、命令与性能契约以 [`runtime-contracts-v1.md`](./runtime-contracts-v1.md) 为准。

### 5.4 Agent scope

- R1 实现 Claude Code Adapter；R2 实现 Codex Adapter，以第二个真实 Adapter 验证 seam。
- Adapter 与应用一起发布，声明支持的 Agent CLI 版本范围。
- Full / Launch-level 只是 UI 汇总；核心流程只按 Capability 决策。
- Kimi、PI、Qoder 延后，不进入 v1 发布门槛。

### 5.5 Terminal

- 全深度体验仍是目标：输入延迟、Unicode/emoji、WebGL 回退、Snapshot/delta 和高输出负载均有验收。
- v1 默认使用上游 xterm.js 与 node-pty；下游补丁需要已测量缺口、owner、预算与回归测试。
- 上游优先与补丁证据闸门见 [ADR-0003](../adr/0003-upstream-first-terminal.md)。

### 5.6 Trust

- Repository 默认 untrusted；Daemon 使用当前用户权限，不以 root 执行 Agent。
- Fleet 只控制自己的文件、Git 和生命周期命令，不宣称拦截 Agent 内部副作用；见 [ADR-0006](../adr/0006-explicit-trust-without-agent-sandbox.md)。
- 详细信任模型与安全验收以 [`security-v1.md`](./security-v1.md) 为准。

### 5.7 Platform

- v1 仅支持 Apple Silicon macOS；最低 macOS 版本在 R0 完成 Electron、node-pty、Keychain 和公证风险原型后固定。
- 发布物包含签名应用与用户级 LaunchAgent，启用 hardened runtime 并完成 notarization。
- v1 不做自动更新；手动升级仍必须保护 Alive Session 与持久数据。

## 6. Delivery Roadmap

### R0 — Contracts and risk prototypes

交付：

- 状态机、故障矩阵、Control / stream、安全和持久化契约冻结为 v1 draft。
- 验证 LaunchAgent 下 PATH、shell、Keychain 和 Agent discovery。
- 实测 Daemon crash 时 node-pty、子进程组和孤儿进程行为。
- 验证 binary stream framing 在 10 Session 高输出下的吞吐与背压。
- 探测 Claude Code / Codex 的 Hook、Transcript、Resume 和权限参数，形成 Capability fixture。
- 用上游 xterm.js / node-pty 跑终端性能与 Unicode 原型，记录是否触发 ADR-0003 的补丁证据闸门。

Exit：每个风险原型都有可重复脚本或 fixture、结论和失败门槛；不存在依赖“以后再补”的核心可靠性承诺。

### R1 — Single-Agent reliable loop

交付 Claude Code 的单 Task 闭环：

- Repository Trust、Workspace、Task、Worktree 和 Profile。
- Daemon、SQLite、chunk store、Session、Control Lease 和最简 UI。
- start、attach、follow-up、stop、cancel、retry、explicit resume。
- UI 生命周期独立、准确的 Lost / Interrupted / Uncertain 和 Reconciliation。

Exit：通过 runtime contract 中的单 Session、幂等、UI 重启、Daemon crash、Host restart simulation、存储崩溃点与安全测试。

### R2 — Fleet ×N and second Adapter

交付：

- Host / Agent 并发上限、稳定队列、多 Worktree 和 Fleet 看板。
- Codex Adapter 与跨 Adapter 契约 fixture。
- 10 个并发 Session 的隔离、背压和性能验收。

Exit：第二个真实 Adapter 不需要修改 Task Orchestrator 的 Agent 特例；否则先修正 Adapter interface。

### R3 — Evidence and read-only Git

交付：

- Task 时间线、Observation provenance、Artifact 与结果页。
- 文件树、status、diff、ahead / behind 和 branch 来源的只读视图。
- 去重桌面通知与数据缺口展示。

### R4 — Hardening and terminal depth

交付：

- 性能预算、Unicode/emoji、WebGL 回退、golden 回归。
- 磁盘压力、数据清理、migration、损坏恢复和安全加固。
- 只有满足 ADR-0003 的证据闸门时才包含必要的下游补丁。

### R5 — Distribution

交付：

- 签名、公证、用户级 LaunchAgent 安装。
- 有 Alive Session 时的升级阻止 / drain。
- 卸载时保留或清理 Daemon、Workspace 数据与 Artifact。

## 8. v1 Release Gates

- [`runtime-contracts-v1.md`](./runtime-contracts-v1.md) 的 Required Contract Tests 全部通过。
- [`security-v1.md`](./security-v1.md) 的 Required Security Tests 全部通过。
- Claude Code 与 Codex Adapter 在声明的 CLI 版本上通过同一套 fixture。
- Renderer 连续重载 10 次和 Electron 强制退出均不改变 Alive Agent PID。
- Daemon 强制崩溃与 Host restart simulation 后不出现假 Alive，也不自动启动 replacement。
- 10 个并发 Session 满足输入、恢复、零持久化字节丢失和零串线预算。
- 签名安装、手动升级、drain、保留数据卸载和完整清理卸载均通过干净机器测试。

## 9. Explicitly Out of v1

- Kimi、PI、Qoder 及动态加载的第三方 Adapter。
- 内置文件编辑器。
- commit、branch create/delete、reset、force push、push 等 Git 写界面。
- Daemon 或 Host 丢失后的自动 resume / retry。
- 同一 PTY 跨 Daemon 崩溃或 Host 重启存活；per-Session supervisor。
- 未经证据闸门的 xterm.js / node-pty 下游补丁。
- Fleet 级 Agent sandbox、临时 VM 和完整网络隔离。
- DAG、依赖调度、approval gate 和可恢复工作流引擎。
- SSH Host、Relay 和 known-host 固定。
- Browser 验证、Computer Use、Emulator。
- Web / Mobile 多客户端、设备配对和 E2EE。
- 自动更新。
- 企业 SSO、RBAC、组织策略和成本配额。
- AI Vault、native chat 和跨 Agent Transcript 索引。
