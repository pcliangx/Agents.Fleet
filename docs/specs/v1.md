## 1. Problem

同时使用多个 CLI 编码 Agent 很费精力：每个 Agent 都需要一个终端持续观察；普通终端或桌面应用关闭后，进程与上下文容易丢失；多个 Agent 在同一 Worktree 工作时会互相覆盖；用户缺少统一、可信的状态与结果视图。

用户希望把多个 Task 交给一个 Fleet 后离开电脑，回来时能够准确知道：

- 哪些 Agent 仍然 Alive；
- 哪些只是 Restored View；
- 哪些 Attempt 已失败、中断或处于 Uncertain；
- 每个 Attempt 修改、验证和遗留了什么。

## 2. Product Promise

Agents.Fleet v1 是本地优先的 macOS 桌面应用与用户级 Daemon：

- 每个执行中的 Task 使用 Fleet 独占分配的 Worktree；它提供 checkout 与调度分离，不构成 Agent 文件访问 sandbox。
- Daemon 独立于 Electron UI，UI 关闭或崩溃不终止 Alive Session。
- 用户重新打开 UI 后可 attach 同一个 Alive Session，或读取已经持久化的 Restored View。
- Daemon 或 Host 重启后，系统保留 Task、Attempt、Observation 和 Artifact，执行 Reconciliation，并如实显示 Interrupted / Uncertain。
- 原进程与 PTY 不会被描述为“跨机器重启存活”；resume 需要用户确认，并创建新的 Attempt 与 Session。
- Session 原始字节先完成持久化再向 UI 发布；Snapshot 只覆盖可证明安全的持久化边界，剩余字节作为 delta 恢复。
- Agents.Fleet 使用用户自己的 Agent、账号与 Host，不重新实现 Agent 的推理和工具循环。

## 3. Product Principles

1. **Truth before continuity**：宁可显示 Lost / Interrupted / Uncertain，也不把历史画面伪装成 Alive。
2. **UI is a projection**：UI 只订阅和提交命令，不拥有权威状态。
3. **Separation by Worktree**：Fleet 管理的 Worktree 不被并发 Task 共享；这只是 Fleet 归属和 checkout 分离，不限制 Agent 访问其他路径。
4. **Evidence over self-report**：结果由 Observation、Artifact 和 Git 事实支撑，不只展示 Agent 自述。
5. **Explicit trust**：Repository 默认 untrusted；安全承诺只覆盖 Fleet 真正能强制的行为。
6. **One reliable slice before breadth**：先完成单 Agent 可靠闭环，再增加并发和第二个 Adapter。

## 4. v1 User Stories

### 4.1 Trust, environment, and Workspace

- **TRUST-1**：首次选择 Repository candidate 时，我必须在 Electron Main 的原生确认中看到 Daemon 提供的 canonical path、文件系统 identity、计划使用的 Agent、数据保存位置、PendingValidation 验证计划和 Agent 可能拥有的 Host 权限上界后，显式授予 Repository Trust；首次确认只进入 PendingValidation，受限 Git 验证成功且 identity 未漂移后才变为 Active，该授权本身不创建 Attempt 或启动 Agent。
- **TRUST-2**：Repository Trust 变为 Active 后，我能选择 Manual / Balanced / YOLO；每次首次启动、retry 或 resume 前，都在原生 Launch Confirmation 中看到经验证的 executable / interpreter / package closure identity、coverage 与观察时间、对应 Agent 的 effective mapping、缺失控制、脱敏 argv、Environment Snapshot、Worktree target 与 `baseCommitSha`，并对这次 LaunchIntent 单独确认。
- **ENV-1**：我能看到所选 Agent 与运行时的路径、版本、Capability 和可调用状态；首次 Repository Trust 确认前不会执行 Git、shell、Agent 或 Repository 内容，PendingValidation 只运行受限 Git 验证，Active 后的实际启动环境可被审阅。
- **WORKSPACE-1**：我能选择 canonical root 作为 Repository candidate；首次 Trust 确认进入 PendingValidation 后，系统才通过受限 Git Interface 验证 Git root、Repository identity、当前 commit 及可用的 branch / base ref，并且只在验证为 v1 支持的 Repository 形态后激活 Trust、建立 Workspace；不支持的形态返回明确原因且不留下可执行 Workspace。
- **PROFILE-1**：我能保存只含 secret reference、不含明文秘密的版本化 Agent Profile；创建 Attempt 时同时保存不可变的 Profile 与 Task specification 快照。

### 4.2 Task, Attempt, and Worktree

- **TASK-1**：我能创建 Task，填写目标、背景、约束和验收标准。
- **WORKTREE-1**：首次执行 Task 时，系统只使用 `CreateFromBase`，从明确的 `baseCommitSha` 创建独立 Worktree；并发 Task 不共享 Worktree。
- **WORKTREE-2**：我能查看 Worktree 的路径、identity、branch 或 detached 状态、Task、Alive Session、脏状态、比较基准 SHA、只基于本地 refs 的 ahead / behind 及其 freshness，以及清理阻塞原因。
- **WORKTREE-3**：系统只会移除 Fleet-managed、identity 匹配且已确认 clean 的 Worktree；它会检查非终态 Attempt、Alive Session、未决 Process Disposition、相对显式 integration target 尚未合并的 commit 和目标 identity，并保留 branch。
- **TASK-2**：每次首次执行、retry 或 resume 都创建新的 Attempt，旧历史不被覆盖。
- **TASK-3**：我能看到 TaskView 的 Draft / Queued / Running / Waiting / Succeeded / Failed / Interrupted / Uncertain / Cancelled；同时单独看到当前或最后 Attempt 的原始状态、Starting / Stopping phase、来源、等待原因和终结原因。
- **TASK-4**：`RequestAttemptStop`、`CancelTask` 与 `TerminateSession` 是三个明确命令；它们分别显示目标 Attempt、Task 或 Session、实际进程终止范围，并明确说明停止不会自动删除 Worktree 修改，但可能留下部分完成的 staged / unstaged / untracked 内容。
- **TASK-5**：retry 必须显式选择 `ContinueCurrentWorktree`、`Rebaseline` 或 `FromCommit`。预览会说明复用还是创建 Worktree、`baseCommitSha`、dirty / untracked 内容是否保留；新 Worktree 模式绝不隐式复制原 Worktree 的未提交或 untracked 内容。
- **TASK-6**：Interrupted / Uncertain Attempt 不会自动重新执行；只有 Adapter 声明 Resume Capability、遗留 Process Disposition 已允许 replacement、我显式选择 TASK-5 的三种 Worktree mode 之一并确认重复副作用风险时，系统才允许 resume，并创建新的 Attempt 与 Session。

### 4.3 Agent and Fleet

- **AGENT-1**：v1 支持 Claude Code 与 Codex；UI 按 Adapter Capability 展示 Hook、Transcript、Resume 和 Permission Mapping。
- **AGENT-2**：没有权威 Observation 的状态必须标记 inferred；没有 Resume Capability 时不显示 resume 操作。
- **FLEET-1**：我能在独立 Worktree 中同时运行多个 Task。
- **FLEET-2**：系统按 Host 与 Agent 并发上限把超限 Attempt 放入可见队列，空槽后按稳定顺序启动。
- **FLEET-3**：Fleet 看板展示 TaskView 状态、当前或最后 Attempt 状态、Agent、Worktree、等待原因、最近 Observation、数据 freshness 和需要用户处理的项目。

### 4.4 Session continuity

- **SESSION-1**：关闭、重载或终止 Electron UI 后，Daemon 中的 Alive Session 继续运行。
- **SESSION-2**：重新打开 UI 后，我能在 RT-PERF-03 定义的负载与 p95 预算内 attach 同一个 Alive Session，看到安全 Snapshot 与 durable delta，并在取得 Control Lease 后继续输入。
- **SESSION-3**：我能明确区分 Alive、Exited、Lost 与 Restored View；Restored View 不能输入。
- **SESSION-4**：多个客户端可以观察同一 Session，但同一时刻只有一个 Attachment 持有 Control Lease。
- **SESSION-5**：旧 Attachment、旧 generation 或旧 fencing token 不能 `WriteSessionInput`、`ResizeSession` 或 `TerminateSession`；`RequestAttemptStop` 不依赖 Attachment Lease，但必须明确确认影响。
- **SESSION-6**：海量输出不会导致跨 Session 串线或静默丢失；达到存储硬上限时 Attempt 明确进入 Waiting / StoragePressure，产生该输出且仍可能继续写入的相关 Session 进程组被暂停。
- **SESSION-7**：我能向 Alive Agent Session 发送 follow-up；输入在写入 PTY 前记录为 Input Intent，交给 PTY owner 后记录为 Dispatched，崩溃窗口明确显示 Uncertain 而不会自动重放。
- **SESSION-8**：一个 Attempt 有多个 Session 时，primary 结果与 blocking Session 决定 Attempt 是否终结；non-blocking Session 继续可见并阻止 Worktree dispose、Daemon / runtime 升级与卸载。

### 4.5 Observation and results

- **OBS-1**：Task 时间线汇总创建、Attempt、输入、状态、Git 与完成事件，并区分 authoritative / inferred。
- **OBS-2**：我能查看 Worktree 文件树、staged / unstaged / untracked 状态、行级 diff、ahead / behind 和 branch 来源；v1 中这些能力只读，所有比较都展示解析后的 SHA、观察时间和“仅本地 refs / freshness 未知”等限制。
- **OBS-3**：Attempt 结果页展示带 provenance、content hash 和观察时间的 Artifact、文件变化、commit、Fleet 实际观察到的测试结果、风险和数据缺口；Agent 自述的测试或完成声明必须与权威观察分开。
- **OBS-4**：Agent 请求输入、Attempt 完成、失败、Interrupted、Uncertain 或 StoragePressure 时，我收到去重的桌面通知；通知投递失败不改变 Attempt 结果。

### 4.6 Security and distribution

- **SEC-1**：未授权客户端不能调用 Host 能力；Renderer 不能绕过 Electron Main 与 Daemon 的 Control Interface，且导航、窗口、权限和 IPC 默认拒绝。
- **SEC-2**：Fleet 自己的文件操作不能通过绝对路径、`..`、symlink 或竞态越过该操作声明并验证过的 Repository、Worktree 或 app-data root；私有 FileBroker 用对应 directory fd 完成检查和打开，UI 明确说明这不是 Agent sandbox。
- **SEC-3**：Fleet 管理的秘密进入 OS Keychain；原始 PTY / Input Intent / 恢复 Snapshot / Artifact content 按敏感本地数据保护，普通日志、时间线和默认导出才执行 best-effort redaction，并明确提示其限制。
- **DIST-1**：我能用签名并公证的 macOS 安装包安装应用；完整、不可裁剪的发布组件清单与完整性要求由 RT-DIST-01 和 SV1-SUPPLY-01 定义，用户级 LaunchAgent 由系统托管。
- **DIST-2**：升级、卸载或数据清理遇到 Alive Session、未决 Process Disposition、Fleet-managed Worktree 或 Artifact 时，会显示影响并要求 drain、保留或取消；“完整清理”不能越过 Worktree dispose 规则，存在脏或其他阻塞 Worktree 时必须保留并报告人工处理步骤。
- **PLATFORM-1**：v1 只发布到 Apple Silicon macOS；R0 必须冻结含最低 macOS 版本、最低硬件、Electron / WebGL2 / DOM、node-pty、Keychain 与公证兼容性的 `SupportedPlatformMatrix`，之后所有性能和分发验收都引用同一矩阵。

## 5. Architecture and Module Decisions

### 5.1 Process model

- 用户级 LaunchAgent 运行 Daemon，拥有 PTY、子进程与生命周期权威；见 [ADR-0001](../adr/0001-user-launchagent-and-reconciliation-limits.md)。
- Electron Main 是 Control / stream transport Adapter，Renderer 不直接取得 Host 能力。
- 发布包严格实现 RT-DIST-01 / SV1-SUPPLY-01 的完整 release manifest；LaunchAgent 使用签名包内绝对路径和清理后的环境。
- v1 的 Daemon crash 可能使 Session Lost；不引入 per-Session supervisor，也不承诺同一 PTY 跨 Daemon 或 Host 重启存活。

### 5.2 Deep Modules

- **Control Dispatcher Module**：只负责版本、鉴权、幂等、确认与路由。
- **Task Orchestrator Module**：拥有 Attempt 状态机、队列、并发配额和 Reconciliation 决策。
- **Session Runtime Module**：对外拥有 PTY 生命周期、attach、输入、resize、terminate、Snapshot / delta 与 Control Lease；其私有 Implementation 是 ProcessSupervisor、ByteJournal、SnapshotCoordinator、StreamBroker 与 LeaseManager。
- **Terminal Surface Module**：接收 Snapshot / delta 与用户输入，隐藏 xterm.js instance、官方 addon、WebGL2 / DOM、IME 和输入编码。
- **Worktree Manager Module**：拥有 provision、inspect、dispose 及全部 Git/path 安全不变量；FileBroker 是其私有 native Implementation。
- **Agent Adapter Module**：隐藏 Agent 差异，并以 Capability 描述真实能力；见 [ADR-0002](../adr/0002-agent-adapter-capabilities.md)。
- **Desktop Bridge Module**：向 Renderer 提供类型化 Control Interface、绑定 Attachment 的 MessagePort、原生确认与通知激活。
- **Host Environment Module**：在中立 cwd 和清理环境中探测 executable identity 与生成不可变启动环境。
- **Notification Gateway Module**：投递持久化 Notification Intent 并将点击路由回已鉴权的 Task / Attempt。
- **Evidence Recorder Module**：接收 Worktree、Session、Adapter 与 test runner 的候选证据，保存带 provenance / hash / confidence 的 Artifact、GitObservation、test result 与 data gap。
- **Fleet Projection Module**：从权威状态和领域事件生成 UI 读模型。

产品调用者与跨 Module 契约测试只依赖这些 Module Interface，不把私有 Implementation 变成跨模块依赖。私有组件仍可进行独立单元测试、故障注入、静态检查和构建产物检查，以验证 fsync、native boundary、package load 与 TOCTOU 等无法只靠黑盒覆盖的保证。

### 5.3 Identity, persistence, and stream

- Task → Attempt → Session → Attachment 身份显式分层；attach 默认观察、控制权显式取得；见 [ADR-0004](../adr/0004-identity-and-observe-first-control.md)。
- SQLite 是生命周期、命令幂等和低频领域事件的唯一权威；PTY 字节使用独立 chunk store；见 [ADR-0005](../adr/0005-lifecycle-and-session-storage.md)。
- control 使用 NDJSON，stream 使用 length-prefixed binary frame。
- Session stream cursor 为 `{sessionId, generation, seq}`；Durable Stream Cursor 是可恢复的上界，Snapshot 的 `coversThroughSeq` 只能落在其内的 parser / UTF-8 安全 checkpoint。
- Input Intent 在 PTY write 前 durable，`Dispatched` 只表示交给 PTY owner；不能伪称 Agent 已消费输入。
- 详细状态、故障矩阵、命令与性能契约以 [`runtime-contracts-v1.md`](./runtime-contracts-v1.md) 为准。

### 5.4 Agent scope

- R1 实现 Claude Code Adapter；R2 实现 Codex Adapter，以第二个真实 Adapter 验证 Seam。
- Adapter 与应用一起发布，声明支持的 Agent CLI 版本范围。
- Full / Launch-level 只是 UI 汇总；核心流程只按 Capability 决策。
- Repository Trust 首次确认前只读取 Host 元数据并形成候选 executable；PendingValidation 只运行受限 Git 验证，Trust 变为 Active 后才在中立 cwd、清理环境中执行版本 / Capability probe，再生成逐次 Launch Confirmation；实际 Agent 启动才进入目标 Worktree。
- Kimi、PI、Qoder 延后，不进入 v1 发布门槛。

### 5.5 Terminal

- Electron Renderer 使用随应用发布且精确锁定版本的 `@xterm/xterm`；官方 WebGL addon 是首选 WebGL2 绘制路径，DOM renderer 是强制回退。
- 用户级 Daemon 的 ProcessSupervisor 使用 `node-pty` 与 `encoding: null` 拥有 PTY 与 Agent 进程；Renderer、Electron Main 和 Snapshot Worker 不加载 native PTY addon，也不直接连接 Daemon socket。
- 全深度体验包括输入延迟、Unicode / emoji / CJK / IME、reflow、selection、clipboard、accessibility、Snapshot / delta、绘制路径切换和高输出负载。
- Snapshot 只在 `parserGround && utf8DecoderEmpty` 的 durable 安全 checkpoint 生成；无法证明时不推进 cursor，须先完成 R0 上游验证或最小补丁。
- allowlist 仅含 `@xterm/xterm`、`@xterm/headless`、`@xterm/addon-webgl`、`@xterm/addon-serialize` 与 `@xterm/addon-unicode11`（后者修正 emoji / CJK 宽度）；不加载 `addon-image`，效果由私有 TerminalEffectPolicy 控制。运行时不下载终端代码。allowlist 的 5 包决策见 [ADR-0007](../adr/0007-terminal-allowlist-unicode11-addon.md)（supersede ADR-0003 的 allowlist 部分）。

### 5.6 Trust

- Repository 默认 untrusted；Daemon 使用当前用户权限，不以 root 执行 Agent。
- Fleet 只控制自己的文件、Git 和生命周期命令，不宣称拦截 Agent 内部副作用；见 [ADR-0006](../adr/0006-explicit-trust-without-agent-sandbox.md)。
- Electron 使用私有 app protocol、CSP、sandbox、context isolation、最小 preload Interface、sender / frame 校验和默认拒绝的 navigation / permission；FileBroker 使用 native directory-fd 路径操作。
- 详细信任模型与安全验收以 [`security-v1.md`](./security-v1.md) 为准。

### 5.7 Platform

- v1 仅支持 Apple Silicon macOS；最低 macOS 与最低硬件必须作为 PLATFORM-1 的 `SupportedPlatformMatrix` 在 R0 完成 Electron WebGL2 / DOM、xterm.js headless Snapshot、node-pty、Keychain 和公证风险原型后固定。
- 发布物包含签名应用与用户级 LaunchAgent，启用 hardened runtime 并完成 notarization。
- v1 不做自动更新；手动升级仍必须保护 Alive Session 与持久数据。

## 6. Delivery Roadmap

### R0 — Contracts and risk prototypes

交付：

- 状态机、故障矩阵、Control / stream、安全、Worktree、Evidence 和持久化契约形成可审计的 R0 Baseline candidate；仍有未决核心风险时保持 Draft。
- 验证 LaunchAgent 下 PATH、shell、Keychain 和 Agent discovery。
- 实测 Daemon crash 时 node-pty、子进程组和孤儿进程行为。
- 按 RT-PERF-08 的固定 10 Session 负载验证 binary stream framing 的吞吐与背压。
- 在 UTF-8、CSI、OSC、DCS 的每个 byte boundary 进行 Snapshot + delta 原型，证明 `parserGround && utf8DecoderEmpty` checkpoint；若上游不能证明，冻结最小补丁的 owner、hash、fixture、升级预算和删除条件。
- 验证 chunk checksum、fsync、rename、directory fsync、SQLite cursor commit 与 publish 的每个崩溃边界，以及 Input Intent / Dispatched 的崩溃窗口。
- 探测 Claude Code / Codex 的 Hook、Transcript、Resume 和权限参数，形成 Capability fixture。
- 验证首次 Repository Trust 确认前不执行 Git、Agent、shell 或 Repository 内容；PendingValidation 只运行受限 Git 验证，Active 后的 Host Environment probe 使用中立 cwd、清理环境和显式 executable identity。
- 锁定兼容的 `@xterm/xterm`、`@xterm/headless`、`@xterm/addon-webgl`、`@xterm/addon-serialize` 与 `@xterm/addon-unicode11` 精确版本和包完整性，并验证 Renderer 与 Daemon headless Snapshot Worker 的 terminal engine identity 一致。
- 用同一 Terminal Surface Interface 验证 WebGL2 与强制 DOM 两条路径，覆盖 WebGL 初始化失败与 context lost、Unicode / emoji / CJK / IME、reflow、selection、clipboard、accessibility、Snapshot 重建和 RT-PERF-08 固定负载。
- 验证 `node-pty` 只存在于独立 Daemon，Electron Main / Renderer 退出或升级不会接管或重复 spawn PTY。
- 验证私有 app protocol、CSP、sender / frame 校验、Electron fuse、Notification Gateway、native FileBroker，以及 Worktree checkout 对 hook / filter / submodule 等外部程序入口的 fail-closed 边界。
- 验证本地 socket peer identity、Keychain capability token 的 nonce / transcript 双向 proof、重放与版本降级边界。
- 在 active / hidden / Electron closed 三类负载下冻结 Renderer / Main / Daemon 的 RSS、CPU、paint、durable lag 与 Snapshot 性能预算。
- 冻结 PLATFORM-1 的 `SupportedPlatformMatrix`；没有最低 macOS、最低硬件和两条绘制路径的结果时不得进入 R1。
- 冻结 `RuntimeLimitProfile`，统一 Control / stream、Renderer queue、terminal、challenge、Observation 与 Notification 的所有硬上限。
